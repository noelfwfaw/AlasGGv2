# AzurLaneAutoScript — GG + 仪表盘 + 每日收益 魔改版

在 [LmeSzinc/AzurLaneAutoScript](https://github.com/LmeSzinc/AzurLaneAutoScript) 之上叠加的一组定制功能。**原版功能全部保留**，界面与用法仍以原版为准，本文只列本版本多出来的东西。

## 功能一览

| 功能 | 一句话说明 |
| --- | --- |
| GG Handler | 加速器自动开关、防弹窗、倍率维持、高战力场景自动降倍率 |
| 仪表盘 + 每日收益 | 12 种资源卡片、今日增量、魔方/钻石周月年汇总 |
| 仓库扫描 | 每天自动记录 18 项仓库材料数量与趋势 |
| 外观装备统计 | 活动外观箱各槽位的持有量与历史 |
| 困难图星期制 | 周一~周日各填一关，均衡收集图纸 |
| 经验检测归并 | 满级检测只影响侵蚀1练级，不再误停短猫 |
| 委托 / 科研开关 | 原本强制开启的两个任务可以关掉 |
| 日服登录强化 | 日服登录卡顿与退回标题画面自动处理 |
| 启动时隐藏模拟器窗口 | 拉起模拟器后窗口消失、任务栏不留图标 |
| 故障推送补全 | 模拟器/设备层出错也会推送，不再静默退出 |
| 模拟器掉线自愈 | 掉线自动拉起并重试，不用人工介入 |
| MAA 插件增强 | 明日方舟插件适配新版 MaaCore，另有一批辅助功能 |
| GUI 修复 | 开关被隐藏、帮助文本导致设置页崩溃 |

## 1. GG Handler（加速器自动控制）

- **自动接管**：运行中自动开关 GG、自动关闭弹出的广告/更新窗口、游戏崩溃后重启模拟器
- **倍率维持**：按设置维持速度倍率，运行中被改掉会自动改回；每个任务可单独决定是否检查 GG 状态
- **战力限制**：演习 / 共斗 / 余烬信标等高战力场景开打前自动降到安全倍率，结束后恢复
- 不开 GG 时行为与原生一致；相关设置项都带中文帮助文本

## 2. 仪表盘与每日收益

- Overview 页 12 张资源卡：石油、金币、钻石、Pt、魔方、行动点、金硬币、紫硬币、核心数据、勋章、功勋、大舰队币
- 每张卡显示当前值（有上下限的同时显示限额）、最近识别时间、今日增量 `| +N`
- 卡片右侧紧邻魔方 / 钻石的今日-本周-本月-今年汇总表
- 「工具 > 数据统计」按年 → 月 → 日分层查看历史，每日明细同时给出当日增量与当日库存绝对值
- 增量为**正差之和**：只累加增长，消耗不会让数字变负，跨天自动归零重算
- 数据全部来自任务运行时的顺手读取，不额外跑任务；数字对应最近一次任务跑到的时刻
- 原始快照保留 30 天，每日汇总长期保留

## 3. 仓库扫描（StorageScan）

- 每天自动进仓库-材料页扫描一次，记录 18 项白名单材料：四类研发图与装备研发图、绝密/机密实验计划、特装型/试作型突破部件、特装原型、心智单元与心智单元II、五类部件T4、喵箱SSR型
- **纯 OCR，无需截图素材**：对翻页相位漂移、行锚点抖动、同名不同品质物品都有专门处理，数量按多页出现次数投票取共识，单页误读会被排除
- **提前收敛**：白名单集齐即停（大号约 5 页）；没有白名单物品的账号连续 3 页无新增即停，不空转
- 调度排在收获之后，记录的是当日收获后的最新数据
- 「工具」组有独立任务卡，可启用调度或手动跑一次；结果在「数据统计」页展示数量、较上次变化与最近 7 次历史
- 限制：只适配国服；扫描约 1~2 分钟，期间不要手动操作游戏

## 4. 外观装备统计（GearSkin）

- 开启方式：活动设置组的「外观装备统计」（默认关闭）。**不单独占用任务卡**，随仓库扫描一起跑
- 每箱固定 18 槽（子弹 / 鱼雷 / 炮弹 / 飞机三型），逐箱记录各外观装备的持有数，不满 18 槽会标注「(不完整)」
- 「数据统计」页按箱分块展示，名称按类型配色，另有总持有数与种类数的历史
- 只在活动期间有数据（活动商店存在外观装备箱，价格 2000 / 限购 10 时）；每箱约 20~27 秒，同样期间不要手动操作
- 非活动期 / 商店已关 / 商店无外观箱 三级守卫自动跳过；统计失败只记 warning，不影响仓库扫描与后续购买

## 5. 困难图星期制

- 困难图设置页提供 7 个字段：周一关卡 ~ 周日关卡，每天可各填不同关卡
- 按服务器时间自动选择当天关卡，均衡收集不同图纸
- 旧版「困难关卡」填过的值会自动填到 7 个字段，升级不丢配置；已手动填写的不会被覆盖
- 舰队、每日刷新等其余逻辑与原版一致

## 6. 经验检测归并

- 满级检测只在**侵蚀1练级**运行，达到目标等级后把侵蚀1练级推迟到次日
- 短猫相接不再做经验检测，不会被满级误停
- 原「每日经验检测」独立任务已移除，设置项保留在侵蚀1练级页面

## 7. 委托 / 科研开关

- 委托、科研从强制开启改为普通开关，关掉后不再安排
- 收获（Reward）仍保持强制开启，它是其他任务正常工作的前提
- 战役中弹出委托完成通知时，若委托任务已关闭，只记日志，不再把开关写回

## 8. 日服登录强化

- 日服黄鸡加载慢，登录阶段单独放宽卡顿判定，登录结束后恢复默认值
- 日服登录成功后若又退回标题画面，会自动再点一次，而不是干等到超时
- 仅日服生效，其他服务器行为不变

## 9. 启动时隐藏模拟器窗口

- 开关：模拟器设置里的「启动时隐藏模拟器窗口」，**默认开启**；仅 MuMu 模拟器 12
- 行为：拉起模拟器后窗口立刻隐藏——不是最小化，**任务栏不留图标**；需要看画面时按 MuMu 老板键（默认 Alt+Q）唤出
- 隐藏期间截图与点击完全正常（画面取自模拟器内部接口，不依赖窗口是否可见）
- 老板键唤出后再启动 / 重启模拟器，会重新自动隐藏
- 启动过程（约 20~90 秒）还没结束时按老板键，窗口会被立刻按回去；想看画面请等启动完成后再按
- 自动降级：旧版 MuMu 不支持隐藏接口、或控制台路径找不到时，退回原行为（启动完成后最小化）；关掉开关也回到原行为
- MAA 插件同步支持同名开关，且**只隐藏本次拉起的那个实例**，不会碰到同时在跑的其他实例

## 10. 故障推送补全

- 以前只有「任务失败」会推送，模拟器起不来、设备初始化失败这类错误是静默退出的；现在一并推送：
  - 设备 / 模拟器初始化失败
  - 调度循环异常终止
  - 模拟器掉线且自动恢复失败
  - GG 包名填错（随即退出）
  - GG 运行中 uiautomator 掉线并重启模拟器
  - GG 状态连续多次检查异常
- **同一次故障只推一条**：精确原因先发，兜底的那条自动跳过
- GG 这类会反复出现的故障 10 分钟内只推一次，避免刷屏
- 配置文件损坏、程序读不到配置时，仍会尝试直接从磁盘读推送配置发一条
- 未配置推送服务时静默跳过，不报错、不影响程序退出

## 11. 模拟器掉线自愈与「关闭模拟器」收尾

- 完成所有任务后可选择关闭模拟器，下个任务开始前自动拉起（ALAS 与 MAA 都支持）
- 每条任务开始前做一次约 30ms 的设备探测；掉线就重新枚举实例、修正端口漂移、拉起模拟器并重连，不再让整个实例直接退出
- 任务运行中掉线：确认设备真的不在时拉起并重试该任务一次，其余情况维持原退出行为
- 距下个任务不足 3 分钟不关模拟器（关掉再拉起要十几秒，短空档得不偿失）
- 就绪判定等到系统启动完成才放行，避免 adb 端口刚通就派任务导致崩溃
- 等待期间每 10 秒按实例名重查一次端口，端口变了自动更新，不会白等到超时
- MAA 插件额外差异：启动时只做配置体检（找不到实例立即报错），**实际拉起延后到任务到点**，避免「拉起 → 队列又空 → 又关」的空转；等待期间每 5 秒主动连接 adb（MuMu 不会自己注册端口）

## 12. MAA 插件（明日方舟 · AlasMaaBridge）

- 按 MaaCore v6.20.1 重新适配：生息演算、肉鸽 6 主题、领取奖励补齐限时开采与限时签到，以及一批回调与兼容修复
- **更新 MAA**：资源增量更新（Stable / Beta / Nightly），可选同时更新本体；本体被占用时下次启动再装，且不会覆盖用户数据
- **更新数据**：识别干员 box 与仓库，结果存 `config/maa/`；**干员培养**：直接填 MAA 原生培养计划 JSON
- **完成所有任务后**：主页面待机 / 关闭游戏 / 关闭模拟器
- **自定义包名**：留空沿用 MAA 自带映射，填写后覆盖；启动前校验设备上确实装了这个包，缺失时列出相关包并请求人工介入
- **辅助启动**（默认关闭）：用音量键开关客户端悬浮辅助面板，适配「彻底隐藏灵动岛」的魔改客户端
- **启动时隐藏模拟器窗口**：见第 9 节

## 13. GUI 修复

- 科研启用开关被样式误伤而隐藏，已修复显示
- 帮助文本里的 JSON 示例花括号导致设置页 KeyError 崩溃，四语言文案统一转义

## 配置文件位置

除原版的 `config/<实例名>.json` 外：

- `config/stats/<实例名>.json` —— 每日资源统计
- `config/maa/operbox.json`、`config/maa/depot.json` —— MAA 干员 box 与仓库识别结果
- `log/storage_scan/<实例名>/records.json`、`gear_skin.json` —— 仓库扫描与外观装备记录

## 已知限制

- **科研消耗的魔方无法精确统计**：只按库存正差累加；「手动领邮件补偿但没跑任务」的情况不会被记录
- **Pt 在活动结束后清零**：增量从 0 重新开始（与实际一致）
- **外观装备统计只在活动期间有数据**：活动结束后不再采集，旧记录保留在历史里
- **仓库扫描只适配国服**，扫描期间不能手动操作游戏
- **启动时隐藏窗口只支持 MuMu 模拟器 12（Windows）**
