## 1. 需求（用户原话）

> 我发现隐藏好的辅助还是会被误触出来，导致遮挡。隐藏修改为「彻底隐藏灵动岛（自动开音量键菜单）」，
> 利用调音量打开和关闭辅助。注意已经默认打开了彻底隐藏，所以之前的打开辅助方式和关闭辅助都要改。
> 增加音量时打开，减少音量时关闭。所以整体流程可以优化，音量打开辅助-同意条款-进入辅助-音量关闭辅助。

新流程（唯一正确行为）：

```
音量+（打开辅助面板）
  → 同意条款（若出现声明页，需下滑到底再点「我已阅读并完全同意以上声明」）
  → 进入辅助（点「进入辅助」，密码依赖辅助自己记住）
音量-（关闭辅助面板）
  → 确认面板消失 → 完成
```

用户侧前提：**魔改包设置里「彻底隐藏灵动岛(自动开音量键菜单)」已开启**（用户已确认），
开启后灵动岛完全消失、不留热区，因此误触问题从根源消除。

## 2. 为什么要改（含已定位的坑）

### 2.1 现状问题

旧流程最后一步是点「隐藏灵动岛(点击原位置恢复)」。该方式**保留原位置的隐形热区**，
运行中被点到就会把辅助重新弹出来，遮挡 MAA 操作——这是用户实测反馈的。

### 2.2 打开方式必须换

彻底隐藏后灵动岛不可见也不可点，旧的 `ISLAND_POINTS`（`assist.py:45`，`(639,33)` / `(660,33)`）
点击逻辑彻底失效，改用音量键。

### 2.3 ⚠️ 齿轮与隐藏分支必须停用（不要只是"降低优先级"）

旧状态机里有 `OPEN_SETTINGS`（`:186-187`，点齿轮进设置）与 `HIDE_ISLAND`（`:174`，点隐藏按钮）
两个分支。新流程下如果它们仍生效，会做两件坏事：

1. 点齿轮进设置页 → 点到「隐藏灵动岛(点击原位置恢复)」→ **把用户刚开的"彻底隐藏"设置改回去**，
   误触遮挡问题原样复发；
2. 在无热区可点的前提下，这些点击本身就是无效操作，还会拖长流程。

因此：**移除这两个分支的触发条件**（不是降低优先级，是让它们不会被走到）。
`assist_gear` / `assist_hide` 两个模板建议同步从 `TEMPLATES`（`:31-38`）移除，
若保留用于诊断则必须确保没有任何分支会因为它们的分数而点击。

### 2.4 顺带收益：绕开上一轮的面板识别问题

上一轮（`doc/prompt-maa-assist-panel-not-matched.md`）的故障是
`assist_panel` + `assist_gear` 双门控在真机分数不足，导致齿轮从不触发。
新流程**不再需要识别功能面板**（不需要 gear，也不需要 assist_panel 作为门控），
实际依赖只剩 `assist_agree` 与 `assist_enter` 两个模板——这两个在真机实测分数是
**0.905 / 0.930**（03:28 日志），稳定过阈值 0.85。**不需要动阈值。**

## 3. 修复步骤

### R1（必须）：封装音量键

在 `MaaAssist` 里加一个发 keyevent 的方法，复用已有的 adb 通道：

```python
KEY_VOLUME_UP = 24      # KEYCODE_VOLUME_UP
KEY_VOLUME_DOWN = 25    # KEYCODE_VOLUME_DOWN
# 调用方式参考已有的 click()：MaaEmulator.shell(serial, 'input keyevent 24')
```

`MaaEmulator.shell(serial, command, timeout=2)` 是静态方法
（`submodule/AlasMaaBridge/module/device/emulator.py:220`），
现有 `click()` 就是 `self.emulator.shell(self.serial, f'input tap {x} {y}')`，照此写即可。
常量放在文件顶部 `ISLAND_POINTS` 附近。

### R2（必须）：打开改为音量+，移除灵动岛点击分支

- 把「点灵动岛打开面板」替换成发一次 `KEY_VOLUME_UP`。
- 移除 `ISLAND_POINTS`（`:45`）的点击循环（`:202-217` 那段）。
  常量可一并删除，不要留成死代码。
- 打开后的成功判据沿用现有思路：面板按钮出现，或画面发生变化
  （`panel_visible()` / `changed()` 已在 `:293`、`:282`）。

### R3（必须）：移除齿轮与隐藏分支

见 2.3。删除 `:174`（hide）与 `:186-187`（gear）的触发；
`panel_visible()`（`:293-307`）里对 `assist_hide` / `assist_panel+gear` 的判据同步清理，
只保留 `agree` / `enter`（以及你决定保留的其它判据）。

### R4（必须）：关闭改为音量-，完成判据同步改

- 确认已进入辅助（点过 `ENTER_ASSIST`，或 `assist_panel` 命中）后，发一次 `KEY_VOLUME_DOWN`。
- 完成判据：按键后重新截图，**`agree` / `enter` 均不命中**即为面板已关闭，日志打印
  `辅助启动: 已完成（音量关闭辅助面板）` 之类的明确信息（沿用现有 `辅助启动:` 前缀风格）。
- 原来的 `clicked_hide` 变量语义改为 `closed`，不要留一个名为 hide 但实际是关面板的标志。

### R5（建议）：打开前先判断面板是否已经开着

`[假设]` 按用户描述「增加音量时打开，减少音量时关闭」理解为**非 toggle**（+ 总是打开）。
但若魔改包实际实现是 toggle（面板已开时按 + 会关闭），直接发 + 会适得其反。
建议：流程开始时先截图，若 `agree` / `enter` / `panel` 任一命中说明面板已开，
**跳过**发 `KEY_VOLUME_UP`，直接进入处理环节。

请把这一条作为「待用户实测确认」项写进你的交付说明，不要自行假设为真后就不再提示。

### R6（建议）：失败兜底与音量净值

- 任何失败/超时分支返回前，确认面板已被关闭（必要时补发一次 `KEY_VOLUME_DOWN`）。
- 正常流程净值：`+1` 打开、`-1` 关闭，**音量回到原值**。请在交付说明里写明这一点；
  若流程中途放弃，净值可能不为 0，用户需要知道。
